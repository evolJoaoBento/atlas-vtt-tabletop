# Atlas Fusion Phase 2 (Shared Logic, Token Height and Movement, No File Engines) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (the user chose inline execution) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both plugins take their grid, level, resource, initiative-side and movement rules from one copy of stock Atlas 0.15 code, show Atlas 0.15's token height and movement steps, and Tabletop no longer carries any code that edits a map file.

**Architecture:** `packages/atlas-shared` (owned by Connect, copied to Tabletop) grows from six files to the rule files both plugins need. Files that import Atlas's texts get a generated stand-in for `i18n`, recorded in `SOURCE.json`. Each plugin's own copy of a rule is replaced by an import from the package and deleted. Token `elevation` and `speed`, and the collection's `movement` rules, flow from Atlas's records to the 3D board and to Connect's players. Tabletop's `TokenWriter` becomes store-only.

**Tech Stack:** TypeScript. Tabletop: esbuild, node:test, Playwright harness. Connect: vite, vitest, eslint. Live check over DevTools in `C:\Users\joaoo\fusion-gate-vault`.

**Spec:** `docs/superpowers/specs/2026-11-13-atlas-fusion-design.md` (section 8 Phase 2; sections 4.2, 9, 11). Phase 1 records: `.superpowers/sdd/2026-11-13-atlas-fusion/`.

## Review Focus

1. **A height on a map that does not count heights.** `unitDistance` 0, negative or not a number, and an `elevation` that is a string, `NaN`, `Infinity` or past 100,000: the figure stands on the floor or at the clamp, and no distance becomes `NaN`. Test: Task 6.
2. **Movement rules that are malformed.** Steps out of order, a multiple of 0, more than four steps, a colour that is not `#rrggbb`, a speed of 0 or a string: the ruler falls back to the plain look, never throws. Test: Tasks 5 and 7.
3. **A token whose speed is unknown.** No `speed` on the token and none in the collection: the ruler shows the distance alone, with no "moved / speed" and no step colour. Test: Task 7.
4. **Hex grids and Large tokens.** Snapping through Atlas's `snapTokenCenter` must land where the old `snapPoint` did for sizes 1 to 4 on square and both hex grids, with and without a grid offset. Test: Task 3.
5. **A board whose map is not held, after the file engines are gone.** Every edit is refused with the bar's text; the initiative panel and the map still draw from the file. Test: Task 9.

## Decisions

- **D1: The texts boundary.** Six of the wanted files import `t` from Atlas's `i18n`, whose closure is about 110 files of texts. The sync writes `src/app/i18n.ts` as a stand-in (`export const t = (key: string): string => key;`), with a `// Generated boundary stand-in` header, and lists it in `SOURCE.json` under `boundaries`. `check-shared` verifies its hash and that it holds nothing else. The index exports no function whose result is a text from `t`.
- **D2: What Phase 2 shares, and what it leaves.**
  - Shared now: token placement and snapping (`grid/gridPlacement`, `gridOffset`, `pixi/token-renderer/tokenSizing`), cell numbering and lattices (`grid/cellNumbering`, `hexLattice`, `squareLattice`), movement cost (`grid/movementCost`), heights (`measure/tokenHeight`, `reachSteps`, `measureGrid`), movement (`measure/movementRules`, `dragMovement`, `dragDistance`, `turnMoves`, `utils/hexColor`), levels (`levels/sceneLevels`, `levelObjects`), resources (`resources/resourceValues`, `resourceTypes`, `resourceSlots`, `visibleResources`, `resourceColors`), initiative sides (`initiative/sides`, `sideOrder`, `initiativeDice`, `defeated`, `gameSystems/diceRules`, `initiativeSideRules`, `characters/playerTokens`), the laser's settings (`tools/laserPointerSettings`), lighting constants (`lighting/lightingConstants`), pin icons (`types/pinIcons`).
  - Left in Connect's old bundle (`vendor/atlas`): `draw`, `dice3d`, `diceDisplay` and the API types. They draw (pixi, three) and are not rules; the dice look is Phase 4.
  - Left as is, with the reason in the spec's section 9: the fog replays (both need `clipper2-ts` or a raster of their own; a shared stroke reader is not worth a package import), the dice judge of a physical throw (Atlas has no function that scores dice that already landed; Task 4 uses Atlas's crit and explosion rules inside it where their signatures fit), and `src/atlasPort/app/{grid,levels,lighting,vision}` (pulled in by the ported panels; they go when the panels are re-synced in Phase 4).
- **D3: Party links are not fused here.** Gate G5 passed from Atlas's source only: the test vault has no Atlas Online campaign, so reading `players.json` cannot be checked live. Connect keeps its own until a vault with a campaign is at hand. This is reported to the user.
- **D4: Height on the board.** A figure is lifted by `riseInCells(tokenHeight(token), measurement)` squares above its level's floor. The measure tool counts the height between two tokens when it starts and ends on a token; the drag ruler does not (a dragged token keeps its height). A spell's hit test takes the token's lifted height.
- **D5: Movement on the ruler.** Both rulers use Atlas's `dragMovement`: the label is "moved / speed" and the line takes the step's colour, when the collection has steps and the token has a speed (its own, else the collection's). Otherwise the ruler is as before. Whether a ruler shows at all follows Atlas's `getDragDistance()` (`always`, `combat`, `never`); on Connect's side the GM's choice is sent with the scene. Movement that adds up over a turn (`countPerTurn`) is not tracked in this phase: each drag counts from zero. This is reported to the user.
- **D6: The two Minor items from Phase 1's review that sit in files this phase opens** (a follow that Atlas leaves by another road waits 15 s; an old Atlas still being asked to switch map) are fixed in Task 1 and Task 8.
